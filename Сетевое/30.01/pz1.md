## Практическое задание

**Тема:** C# + сети: **unicast / broadcast / multicast** (UDP)
**Формат:** мини-проект “Network Messenger Lab” — один репозиторий, 3 режима отправки, один приёмник.

## Цель

1. На практике понять разницу между **unicast**, **broadcast** и **multicast**.
2. Научиться в C# отправлять и принимать **UDP**-пакеты в каждом режиме.
3. Отработать базовые сетевые нюансы: выбор интерфейса, TTL, join/leave multicast-группы, ограничения broadcast.

## Задание (шаги)

### Шаг 1. Структура проекта

Создайте **.NET Console** приложение (или два: Sender/Receiver).
Реализуйте 2 команды (можно через аргументы CLI):

* `receive --mode <unicast|broadcast|multicast> --port <p> [--group <ip>]`
* `send --mode <unicast|broadcast|multicast> --port <p> --message "<text>" [--ip <target>] [--group <ip>]`

**Требование:** один и тот же “движок” отправки/приёма должен работать в 3 режимах (минимум дублирования кода).

### Шаг 2. Unicast (точка-точка)

**Отправка:** отправьте сообщение на конкретный IP:PORT (например, `192.168.1.10:5000` или `127.0.0.1:5000`).
**Приём:** слушайте указанный порт, выводите:

* время получения
* endpoint отправителя
* текст сообщения

Проверьте работу в двух терминалах на одной машине (localhost), затем — на двух машинах в одной сети.

### Шаг 3. Broadcast (один-ко-всем в подсети)

**Отправка:** отправьте UDP-сообщение на broadcast-адрес подсети (например, `255.255.255.255` или `192.168.1.255`) на выбранный порт.
**Приём:** любой приёмник в подсети, слушающий этот порт, должен получить сообщение.

Добавьте опцию:

* `--broadcast <global|subnet>` (глобальный `255.255.255.255` или подсетевой `x.x.x.255`)

### Шаг 4. Multicast (группа подписчиков)

**Группа:** выберите multicast-адрес (например, `239.0.0.222`) и порт (например, `5001`).

**Приём:**

* создайте UDP-сокет и выполните bind на порт
* выполните **Join** multicast-группы
* принимайте сообщения и выводите их аналогично unicast

**Отправка:**

* отправляйте сообщения на `<group>:<port>`
* добавьте параметр `--ttl` (по умолчанию 1) для ограничения распространения пакетов

Пример команд:

* `receive --mode multicast --group 239.0.0.222 --port 5001`
* `send --mode multicast --group 239.0.0.222 --port 5001 --message "hi"`

### Шаг 5. “Мини-протокол” поверх UDP

Реализуйте простой формат сообщения (JSON или собственный):

* `SenderName`
* `MessageId` (GUID)
* `Text`
* `SentAtUtc`

На стороне приёмника:

* игнорируйте дубликаты по `MessageId` в течение N секунд (например, 10–30 секунд)
* выводите статистику (количество полученных, дубликатов, потерь)

### Шаг 6. Наблюдаемость и ручное тестирование

Добавьте:

* логирование адреса назначения (IP/port/mode)
* вывод выбранного локального сетевого интерфейса (если он задаётся)
* режим “spam” — отправку N сообщений с интервалом (например `--count 100 --delay 10ms`)

## Подсказки по ключевым частям

### 1) UDP в C#: что использовать

Рекомендуется использовать `System.Net.Sockets.UdpClient`.

* **Приём:** `ReceiveAsync()` в цикле с `CancellationToken`.
* **Отправка:** `SendAsync(byte[], endpoint)`.

Важно помнить, что UDP не гарантирует доставку, порядок и уникальность сообщений.

### 2) Broadcast: возможные проблемы

Для корректной отправки broadcast-сообщений:

* включите `EnableBroadcast = true`
* используйте корректный broadcast-адрес
* убедитесь, что порт не блокируется фаерволом

Некоторые сети и маршрутизаторы могут ограничивать broadcast-трафик.

### 3) Multicast: join/leave и выбор интерфейса

На стороне приёмника необходимо вступить в группу:

* `JoinMulticastGroup(multicastAddress)`

Если в системе несколько сетевых интерфейсов (Wi-Fi, Ethernet, VPN), может потребоваться явное указание локального интерфейса.

Также обратите внимание:

* TTL — обычно `1` для локальной сети
* multicast-трафик может блокироваться оборудованием или настройками сети

### 4) Порты и bind

Для приёма:

* выполняйте bind на `IPAddress.Any` / `0.0.0.0`
* используйте одинаковый порт для всех слушателей (broadcast/multicast)

### 5) Кодировка и размер сообщений

* используйте UTF-8
* учитывайте MTU: для экспериментов рекомендуется размер сообщений < 1200 байт

## Что проверить перед отправкой (чек-лист)

### Unicast

* [ ] приёмник слушает нужный порт
* [ ] отправка идёт на корректный IP:PORT
* [ ] узлы находятся в одной сети и доступны

### Broadcast

* [ ] `EnableBroadcast = true`
* [ ] корректный broadcast-адрес
* [ ] приёмник слушает `0.0.0.0:<port>`
* [ ] UDP-порт не блокируется фаерволом

### Multicast

* [ ] адрес находится в multicast-диапазоне (224.0.0.0–239.255.255.255)
* [ ] выполнен `JoinMulticastGroup`
* [ ] sender отправляет на `group:port`
* [ ] корректный TTL
* [ ] выбран правильный интерфейс (при необходимости)

### Общее

* [ ] используется UTF-8
* [ ] корректная обработка Ctrl+C (через `CancellationToken`)
* [ ] логирование режима, endpoint и статистики

## Советы по улучшению работы

* Добавьте параметр `--interface <localIp>` для явного выбора сетевого интерфейса.
* Реализуйте autodiscovery:

  * broadcast для поиска сервисов
  * unicast для дальнейшего общения
* Добавьте измерение задержек:

  * timestamp отправки и приёма → RTT
* Реализуйте простой ACK-механизм для unicast:

  * приёмник отправляет `ACK <MessageId>`
  * отправитель считает потери по таймауту
* Реализуйте режим “bridge”:

  * приём multicast
  * ретрансляция unicast-клиентам
