# **Практическое задание: Проектирование и использование библиотек DLL в .NET**

## **Цель задания**
Освоить принципы проектирования библиотек с четким разделением публичного API и внутренней реализации, научиться создавать и использовать DLL в .NET, понимать механизмы загрузки сборок и рефлексии.

## **Задание 1: Проектирование библиотеки**

### **Часть 1.1: Архитектура библиотеки MathOperations**
Спроектируйте библиотеку `MathOperations.dll` со следующей структурой:

```
MathOperations.Core/
├── IMathOperation (интерфейс)
│   ├── Execute(double a, double b)
│   └── string OperationName { get; }
│
├── IAdvancedMath (интерфейс)
│   └── double Power(double x, double y)
│
└── OperationValidator (абстрактный класс)
    ├── abstract bool Validate(double a, double b)
    └── virtual string GetErrorMessage()
```

```
MathOperations.Implementations/
├── BasicCalculator (реализует IMathOperation)
│   ├── Execute() - сложение
│   └── Multiply(double a, double b) - новый метод
│
├── ScientificCalculator (реализует IMathOperation и IAdvancedMath)
│   ├── Execute() - умножение
│   └── Logarithm(double x) - internal метод
│
└── SafeCalculator (наследует OperationValidator, реализует IMathOperation)
    └── Реализуйте проверку деления на ноль
```

```
MathOperations.Utilities/
├── MathFormatter (public класс)
│   ├── FormatResult(double result)
│   └── FormatWithPrecision(double result, int decimals = 2)
│
└── Constants (internal static класс)
    ├── Pi
    └── E
```

### **Часть 1.2: Атрибуты и совместимость**
1. Добавьте атрибут `[Obsolete]` методу `OldCalculateFormat()` в `MathFormatter`
2. Создайте метод `FormatWithCulture()` с параметрами по умолчанию
3. Добавьте атрибут `TargetFramework` для .NET 6.0+

### **Часть 1.3: Internal реализация**
Создайте namespace `MathOperations.Internal` с:
- `CacheManager` (internal класс)
- `PerformanceTracker` (internal структура)
- `HelperMethods` (internal static класс)

### **Часть 1.4: Глобальные утилиты**
Добавьте глобальный класс `MathGlobal` с:
- `GetMathLibraryVersion()` (static метод)
- `IsFeatureEnabled(string feature)` (устаревший метод)

### **Часть 1.5: Тестирование библиотеки**
В том же решении создайте консольное приложение для тестирования всех публичных методов библиотеки.

## **Задание 2: Динамическая загрузка и исследование**

### **Часть 2.1: Assembly Browser**
Создайте приложение `AssemblyExplorer.exe`, которое:
1. Загружает любую DLL через `Assembly.LoadFrom()`
2. Выводит информацию о сборке:
   - Имя, версию, культуру
   - PublicKeyToken (если есть)
   - Целевой фреймворк
3. Находит все публичные типы и их методы
4. Определяет, какие типы являются интерфейсами/классами
5. Помечает устаревшие методы

### **Часть 2.2: Plugin System**
Создайте систему плагинов:
1. Интерфейс `IPlugin` в отдельной DLL `PluginInterface.dll`:
   ```csharp
   public interface IPlugin
   {
       string Name { get; }
       void Execute();
       string GetDescription();
   }
   ```

2. Создайте 2 плагина в отдельных DLL:
   - `TextPlugin.dll` - работа с текстом
   - `MathPlugin.dll` - математические операции

3. Основное приложение `PluginHost.exe`:
   - Сканирует папку `Plugins`
   - Динамически загружает все DLL
   - Находит реализации `IPlugin`
   - Выводит меню с доступными плагинами
   - Выполняет выбранный плагин

## **Подсказки по ключевым частям:**

### **Для Задания 1:**
1. **Разделение ответственности**: Каждый namespace должен иметь четкую цель
2. **Интерфейсы vs Абстрактные классы**: 
   - Интерфейсы для контрактов, которые могут реализовывать разные классы
   - Абстрактные классы для общей реализации
3. **Модификаторы доступа**:
   - `public` - виден всем
   - `internal` - виден только внутри сборки
   - `private` - виден только внутри класса

### **Для Задания 2:**
1. **Рефлексия**: Используйте `Type.GetType()`, `Assembly.GetTypes()`
2. **Обработка ошибок**: Всегда обрабатывайте `FileNotFoundException`, `BadImageFormatException`
3. **Активация**: `Activator.CreateInstance()` для создания объектов

### **Для Задания 3:**
1. **XML комментарии**: Начните с `///`, Visual Studio сгенерирует шаблон
2. **ILDASM**: Отличный инструмент для изучения метаданных
3. **Диаграмма зависимостей**: Можно сделать в draw.io или PlantUML

## **Полезные команды и инструменты:**

```bash
# Сборка и анализ
dotnet build
dotnet build /p:GenerateDocumentationFile=true
ildasm YourLibrary.dll

# Создание NuGet пакета
dotnet pack --configuration Release

# Анализ зависимостей
dotnet list package
dotnet list reference

# Очистка проекта
dotnet clean
dotnet restore
```

**Рекомендуемые инструменты (в т.ч. на будущее):**
- **Visual Studio 2026** или **Visual Studio Code**
- **ILSpy** или **dotPeek** - декомпиляторы
- **PostSharp** - для аспектно-ориентированного программирования
- **NUnit** или **xUnit** - для тестирования
- **Swagger** - для документации API (если будет REST API)
